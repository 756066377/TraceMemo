# 狗头军师的依据与回复生成

狗头军师读取当前会话最近 10、20 或 30 条可用文字与语音转写，结合已填写的关系类型、阶段、本轮目标和补充说明生成回复。时间未知的消息不会补造时间，过去消息中的“明天”也需要结合原消息时间理解。

## 分析结果

侧栏分别展示可见原文、可能意图、关键未知、下一步与停止条件。引用只接受本轮消息中存在的 ID 与连续原文；模型返回虚构引用时会重试一次，仍无效则停止起草。引用通过校验不代表模型的解释必然正确，仍应核对语境。

对方明确要求停止联系时，本轮不生成候选，也不把聊天上传给模型。自己随后继续说话不会解除这条边界；同一发言人明确重启才可解除。多人会话未指定对象时，由模型结合各发言人的原文判断，不能把一人的拒绝当成全群意愿。

边界判断只覆盖本轮取得的上下文，不代表已经检查全部历史记录。引号、转述、否定句和混合语义仍可能存在歧义，必要时应核对原聊天。

## 参考资料

应用携带版本为 `12ee1d6-tracememo.1` 的精简适配资料，来自上游 `shengjidaguai-china/goutoujunshi-jev-chat` 的快照 `12ee1d6582a9270bd44b71a519d21f387542e8e0`。

每轮加载核心规则与自然口吻资料，并根据本轮目标和最近消息选择冲突修复、主动邀约或降低投入主题，最多额外选两份。总量限制为 10000 字符，超出预算的整章不加载。不会从聊天中的路径读取任意文件，也不会自动下载上游更新。

结果包含资料版本、章节与内容 SHA-256 摘要，侧栏列出实际使用的章节。资料缺失时明确显示降级状态，仍可按基础规则分析。

这是原 skill 的部分适配，不包含完整问卷、专题库、演练或自动人物画像。用户保存的关系背景不会因为一次分析而自动更改。

## 候选比较

默认流程为策略判断、起草、候选比较。关闭“比较候选回复”可省去评审调用，适合优先考虑耗时的情况。没有有效评审结果时，候选不显示优先顺序，不把等权结果假装成最佳推荐。

所有候选仍需由用户决定是否编辑、复制或发送。切换会话后，旧分析结果不会进入新会话。

## 真实模型效果评估

评估仅使用合成场景，不读取日常账户配置或真实聊天。需显式配置专用端点与模型；有认证的端点还需提供密钥。

```powershell
$env:REPLY_EVAL_BASE_URL = '你的兼容端点地址'
$env:REPLY_EVAL_MODEL = '你的模型标识'
$env:REPLY_EVAL_API_KEY = '你的评估密钥'
$env:REPLY_EVAL_SAMPLES = '3'
node node_modules/vitest/vitest.mjs run --config vitest.reply-eval.config.ts
```

每个场景分别运行基础提示词与主题资料方案，记录成功状态、策略、原文依据、候选、用量与耗时。默认每场景采样 1 次，可设置为最多 3 次；六个场景、两个方案、三次采样最多执行 36 轮分析，每轮可能包含重试或补写，端点可能收费。

输出为 `output/reply-evaluation/results.json` 和同目录的 `blind-review.md`。后者隐藏方案标签，供人工评价事实一致、口吻自然、目标一致与可执行性。完整明细仍可用于追溯。设置 `REPLY_EVAL_RANK=false` 可另行比较取消候选评审的效果。

这是“使用当前代码的基础提示词”与“增加主题资料”的对照，不是对修改前整个版本的回放。自动通过不代表自然度或真实采纳效果已经提升；这些结论需要人工盲评和实际反馈。
