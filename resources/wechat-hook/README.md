# 微信发送组件：4.1.15.56 x64

## 当前状态：发送暂停

2026-11-08 的真实使用反馈确认：消息可以发出，但微信在随后的异步回调中崩溃。
当前组件构建为 `4.1.15.56-send-suspended-v2`。
登录检测仍可使用；文本和图片接口在已登录时返回 HTTP 503、
`errorCode: SEND_SUSPENDED`，不调用微信内部发送函数。
应用也独立阻止 WeChat-Hook 4.x 发送，保护仍加载旧 DLL 的进程。
安装更新后需退出微信再加载新组件，直接接口调用的保护才会生效。
已经发出的消息不要重发。此版本仅为临时隔离，不代表原生发送崩溃已修复。

在「设置 → 微信发送」中，先手动退出微信，再点「启动微信并连接」。
检测接口后可保存端口 `30001`。已经通过配套启动器启动时，直接检测端口即可。
本项目不会自动退出微信、修改自动更新设置或发送测试消息。

## 登录检测

新版组件逐次读取 4.1.15.56 的原生账号对象，校验构建、虚表、登录位和前后账号快照。
`GET /QueryDB/status` 保留 `IsLogin`：1 为已登录，0 为已退出，-1 为读取失败或未知。
同时返回 `loginState`、`loginDetection: account-memory-v1` 和 `ret`。
文本和图片接口先检查登录；退出或读取异常时返回 HTTP 409，不进入原生发送。
已登录也保持发送暂停，不能以登录成功代替发送兼容性验证。旧版组件仍返回零时需退出微信，
再用新版「启动微信并连接」加载组件；安装包更新不会替换已经载入进程的旧 DLL。

应用保留个人和群聊文本、图片协议，但当前禁止提交。语音、正式 @ 提醒及 XML 转发不在支持范围内。
接口返回成功仅表示已提交到微信内部通道，不代表消息送达。
请求结果不明时不自动重发，请先查看微信，避免重复发送。
消息串行提交，间隔至少两秒；图片副本保留十分钟供微信异步读取。
微信升级后需重新匹配组件，不能强制沿用。

## 组件来源

本地用户提供的 WeChat-Hook 工作区：
`C:/Users/Mason/WorkBuddy/Worktrees/WeChat-Hook/main-b4aae1b8`

登录修复源码保存在本项目 `native/`，通过 `integration.patch` 接入该工作区。
组件由明确指定的本地源码使用 MSVC v143 编译，不使用旧的自动改写版本常量脚本。
构建来源及哈希记录在 `output/wechat-hook-validation/component/provenance.json`。

二进制按本项目约定不提交 Git，但必须随 Windows 安装包一起分发。
换电脑构建时，将上述两个文件放入本目录并核对哈希。
缺失或损坏时启动入口会拒绝执行。需要 VC++ 2015–2022 x64 运行库。
启动时会在应用用户目录生成经哈希校验的 `version.dll` 副本，以适配启动器的模块名检查。

配套服务由微信进程提供，文档声明监听 `0.0.0.0:30001`，没有鉴权。
本项目只连接 `127.0.0.1`；请不要向公网映射此端口。

## 验证边界

原生测试使用生产读取函数和生产文本、图片路由，覆盖登录、退出、未知状态及发送前拦截。
测试发送分支使用计数替身，确认暂停期间调用数为零，不向微信提交消息。
生产读取函数已对本机运行中的微信做只读登录验证。
应用侧另以模拟 HTTP 服务验证协议、排队、错误处理及临时图片生命周期。
配套启动器通过自建测试进程验证文件名兼容性，不操作真实微信。
新 DLL 在真实微信重启后的接口状态仍须核验。
上一版替身测试未覆盖微信原生异步回调，是未拦住本次崩溃的验证缺口。
恢复发送前必须修正回调构造和上下文，并验收真实送达及完成回调后进程存活。
